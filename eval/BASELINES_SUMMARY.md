## 1. Complete comparison matrix (detector × test suite), per binary

Unit: one **binary** (one compiled executable of a program); a binary's inputs and repetitions fold into one verdict. Cell = `TP/(TP+FN), FP/(FP+TN), TO, ERR` in binaries: TP/(TP+FN) over the suite's racy-labelled binaries, FP/(FP+TN) over its race-free-labelled binaries (both exclude binaries that did not finish), TO = binaries with a timed-out run and no report, ERR = binaries that errored. A binary is RACE if any run on any input reports, CLEAN if every run finished and none reports, TO if a run timed out and none reports, otherwise ERR — the same rule for every tool. The racy and fixed builds of a source are two binaries, and so are Indigo3's default and `-DSLOWER_ATOMIC` builds (they lower the atomic helpers differently). A tool's own instrumented build (HiRace's hand-instrumented twin, SuperCollider's shipped binary) counts as the same binary. `-` = slot not available; `0/0` = the suite has such binaries but the tool finished none. The per-run version of this table is `eval/BASELINES_SUMMARY_PER_RUN.md`. The note column gives, per detector, the reason behind its FN, FP and failures, with binary counts in parentheses.

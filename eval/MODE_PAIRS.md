## Definitions

- Source: the vector-clock no-dump recording of each program in the final stores (final-2026-11,final-2026-11-long,final-2026-11-long-sc,final-2026-11-24h-vc,final-2026-11-24h-sc,realworld-2026-10); later stores win, as in latent_census.py. A recording counts only if its mode is saved, not partial and has a complete rep.
- Pass 1 = `sync_dominance.analyze` on the kernel JSON as recorded; pass 2 = the same JSON with `hb_races` and `hb_races_sync_only` removed, `hb_sync_pass` kept (a scalar-clock recording's content; analyze() takes its scalar-clock path).
- A pair is a (kernel name, unordered pc pair) with a verdict in at least one pass; launches of one kernel are merged. Row 2 files each pair under its worst vector-clock class over its launches (structural = Race, latent = Latent). Rows 3 and 4 and the differences count a pair if some launch has the stated pair of verdicts.
- Reported = verdict RACE or SC (strong conflict). Race/Latent = verdict RACE with class structural / latent; Strong conflict = verdict SC.
- Row 3: vector-clock reports the pair; scalar-clock verdict ORDERED with certificate R1 (strength >= observed distance), else R3 (`hb_chain`), or barrier-ordered (the barrier-only clock; not a certificate), else no cert.
- Row 4: vector-clock class latent / latent-sc and a scalar-clock verdict RACE / SC.
- Attribution of a reported-set difference: (a) vector-clock reports, scalar-clock certifies by R3 only; (b) vector-clock reports and the pair is not a candidate on the scalar-clock side; anything else is a finding.
- Population: programs with at least one trace edge, at inter-thread distance, with a read-modify-write pc (an atomic RMW opcode, `HBGraph.atom`) at an endpoint; the RW rows are all real-world recordings. `rmw_pc` in programs.csv is the looser opcode-only flag.
